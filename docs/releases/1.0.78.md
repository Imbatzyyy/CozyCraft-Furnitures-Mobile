# CozyCraft Mobile 1.0.78 — Reserved payments, beautifully in sync

Built on `730230e` (1.0.77). Its motion, navigation and interface improvements
are retained. Android versionCode **79**; iOS marketing version **1.0.78**,
build **66**.

## What's new

- Unfinished GCash/card orders now show **Awaiting payment**, a sage payment
  panel, and the same saved payment deadline as the customer website.
- A live minutes/seconds countdown appears in Orders and the exact order's
  details. Returning to the app never restarts the 15-minute reservation.
- **Continue payment** checks the existing session through the authenticated
  `resume-paymongo-checkout` function and reopens that order's secure PayMongo
  page. It does not create a duplicate order or extend the deadline.
- Paid, expired, offline, opening, retryable-error and missing-deadline legacy
  states are handled. Cash on delivery is excluded.
- Closing the payment browser or a browser-open failure keeps an unpaid order
  recoverable until its server deadline. The former local 30-minute cancellation
  rule has been removed; only the backend/provider confirms expiry.
- At zero, continuation stops and the app explains that final status is being
  checked. Once server cancellation arrives, the reservation-ended state is shown.

## Synchronization and efficiency

- Countdown ticks do **not** call Supabase or PayMongo. Only the small payment
  component rerenders, and interval work pauses while the document is hidden.
- Existing account-filtered Realtime updates refresh affected order IDs. Return
  to foreground, reconnection and expiry use coalesced, targeted refreshes rather
  than fetching the catalog or polling the entire order history every second.
- Resume calls have immediate double-tap protection, a bounded timeout, and
  account/unmount guards. Checkout links are restricted to HTTPS PayMongo hosts.
- Both native bridge allowlists now support resume. Native fallback reads back
  off from 5 to 30 seconds within a bounded two-minute run, reconciling with the
  provider only on its first check. Realtime terminal-state hints trigger immediate
  authenticated verification rather than waiting for the fallback interval.
- An elapsed native monitoring run stops network work without losing the
  browser-dismissal handoff. Native foreground return can initiate another check.

## Backend

No database migration or Edge Function replacement is needed. This release
reuses the deployed shared checkout, resume, reconciliation and expiry services.
Read-only verification on September 30 confirmed `resume-paymongo-checkout`
version 5, `create-paymongo-checkout` version 30, and the active once-per-minute
`cozycraft-expire-paymongo-windows` scheduler with a successful recent run.
The native authenticated HTTP bridge supports the existing function contract
without broadening CORS or weakening customer ownership/security checks.

## Verification

- Storefront TypeScript check and 347 tests passed.
- Angular/native-shell lint and 22 tests passed; 8 Xcode-toolchain tests passed.
- 22 responsive payment layouts/journeys passed in Chromium and WebKit, covering
  iOS/Android styling, 320–844px widths, short landscape, extra-large text,
  running/elapsed timers, retry errors, paid updates and confirmed expiry.
- Tests cover exact-order native handoff, original deadline preservation,
  multiple rapid taps, foreign-account/late responses, offline behavior, unsafe
  URLs, local-only ticks and a single targeted deadline refresh.
- Production storefront/shell, Android debug APK and Xcode 27 unsigned iOS
  Simulator builds passed. Packaged web assets were checked for parity.

These checks do not constitute a physical-device PayMongo transaction. No real
payment was submitted, no customer order was created, and no customer data was
changed during QA. Real card/GCash completion and device handoff should receive
a final physical-device check with the installed 1.0.78 build.

## Installation / publication scope

The GitHub release includes the Android **debug-signed testing APK**. This is not
a Play Store or App Store submission. For iPhone, rebuild/run `ios/App/App.xcodeproj`
with scheme `App` on the selected phone in Xcode; publishing source does not update
an already-installed iPhone app. No physical iPhone installation was performed.
