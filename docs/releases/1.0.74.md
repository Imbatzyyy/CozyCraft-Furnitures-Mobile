# CozyCraft Mobile 1.0.74 — Cross-app reliability fixes

An audited stability update for account flows, welcome vouchers, shopping state, checkout, and the native app shell. The existing visual design and mascot experience are preserved.

## Changes

- Startup, preferences, and app-owned caches recover from denied/full storage. Invalid cached profile, catalog, bag, and payment data no longer crash rendering.
- Rapid wishlist/bag actions are serialized. Failed moves restore only the affected product, and late responses cannot restore a signed-out account's data or overwrite newer shopping edits.
- Reconnect and background refreshes respect current customer actions. A stale welcome-voucher lookup cannot reopen a popup after dismissal.
- Checkout loads delivery addresses independently of optional payment preferences, shows a retry when addresses fail, and preserves a payment method the customer already chose.
- Address forms reject duplicate submissions and select the exact saved row. The client accepts both object and one-row-array API responses instead of confusing the response envelope with an address.
- Default-address changes are atomic: a failed save leaves the existing default intact. The server derives ownership from the signed-in customer and rejects stale drafts from a different account.
- Native navigation, notification, payment and browser-action messages validate their sender. Optional native caching failures do not interrupt callback acknowledgement.
- Account-specific screens and return hints reset on identity changes; superseded toast timers and stale delivery-area results are handled correctly.

## Database deployment

Only migration `20260910110000_atomic_mobile_delivery_addresses.sql` was added to the shared Supabase database before distributing this client. It introduces `save_mobile_delivery_address(jsonb, boolean, uuid)` and does not rewrite existing address data or change the customer website.

The migration ledger matches the repository SQL byte-for-byte (MD5 `908726d0df8495c642434dd1eec299f7`). Transactional tests passed against the deployed function for exact returned rows, one default, invalid/missing targets, ownership isolation, changed-account rejection and anonymous denial. Synthetic fixtures were rolled back; no test accounts remain. Anonymous HTTP calls return **401 / 42501**.

Recommended device checks after updating:

1. Complete or skip the tutorial on an eligible new manual/Google account. Confirm the saved welcome-voucher popup appears, dismiss it, and relaunch to confirm it does not repeat.
2. Rapidly save/unsave an item and move a saved item to the bag; verify the final choice survives refresh/relaunch.
3. Save a delivery address in checkout, switch the default, and confirm the exact selected recipient/address is shown.

Browser tests use controlled backend fixtures and are not proof of physical-device smoothness, live Google authorization, real payment completion, push delivery or invoice-email delivery. No customer emails/SMS or real orders were generated by the audit/release checks, and no app was installed on the user's phone.
