# CozyCraft Mobile 1.0.25

Customer mobile design and accessibility refinement. The customer website and database schema are unchanged.

## Improvements

- Shared reading-size tokens for transactional copy, supporting text, and form labels. Decorative headings and icons retain bounded sizing.
- Larger touch areas, full-width narrow profile fields, readable delivery addresses and payment details, and a simplified email-verification sheet.
- Clearer product pricing and purchase actions, wrapping review filters, compact review metadata, and an in-app review-photo viewer with next/previous navigation and an image-error state.
- Care is accessible from the top header rather than floating over product cards. The existing rounded glass navigation is retained.
- Shorter account-sheet introductions and less duplicate decoration in Care and Payment preferences. Improved order details, status text, product cards, and bag controls.
- CMS document headings and paragraph breaks are preserved; email addresses become actionable links. The original CozyCraft logo is unchanged.
- Keyboard focus is contained within the topmost dialog and returns to its initiating control. Notification rows have keyboard semantics, an accurate Back label, and failure feedback.

## Validation

- Storefront: 27 test files, 171 tests passed; TypeScript passed.
- Ionic shell: 13 tests passed; lint passed.
- Isolated responsive suite: 160 combinations across 320×640, 390×844, 768×1024 and 844×390, using Standard, Comfortable, Large and Extra large text. No detected horizontal overflow or runtime exceptions in the covered fixtures.
- Additional 360×800 and 430×932 checkout/profile/payment/voucher checks passed.
- Interactive checks: review-photo navigation and Escape/focus return, text-size focus loop and return, valid payment-code fixture, short-height payment viewport.
- Rendered guest home, product, sign-in, registration, About, Contact, Terms and Privacy screens; rendered account, order, support, preferences and review fixtures.
- Production storefront and Angular web bundles built; Android debug APK, signed iOS device build, and iOS simulator build succeeded. Native assets are synchronized from the canonical storefront source.

## Scope of verification

The fixture payment test does not send email or charge money. No live purchase, refund, support request, or customer-data mutation was created during design QA. Responsive browser tests and native builds do not establish compatibility with every physical device or replace VoiceOver/TalkBack and real software-keyboard testing. This is a development-device / APK release, not an App Store or Play Store publication.

## Reproducing layout checks

Run `npm --prefix storefront run qa -- --port 5187`, then run `node storefront/qa/design-audit.mjs` with Playwright installed. `PLAYWRIGHT_MODULE` and `BROWSER_PATH` can select an existing local runtime and browser. The QA configuration uses an in-memory Supabase substitute and is not part of the production app.
