# CozyCraft Mobile 1.0.79 — Return to the app after payment

Based on 1.0.78 (`f6d9c5e`). Android versionCode **80**; iOS version
**1.0.79**, build **67**.

## Fixed

- Mobile checkout creation now chooses an app-specific return destination rather
  than the website checkout page. Website-created payments retain website returns.
- A small first-party handoff page opens `com.cozycraft.furniture://payment/return`
  with the exact order ID. A visible **Open CozyCraft app** button remains available
  when Safari/Chrome requires a user gesture or confirmation to open another app.
- Native checkout launch records an exact-order browser navigation preference.
  This repairs the older website return URL for existing sessions resumed from the
  app, without creating another order/session or extending the payment deadline.
- The provider checkout URL is passed in a fragment, not a server query/referrer.
  Only approved HTTPS PayMongo checkout hosts and valid order IDs are accepted.
- Android also accepts the older `/payment/callback` route. The shared legacy
  callback now emits `/payment/return`, matching both native platforms.
- The fallback page finishes loading before requesting the OS handoff, preventing
  a blocked custom scheme from leaving the browser document loading indefinitely.

The browser preference stores only the order ID and a one-hour expiry, not tokens,
customer details or payment data. New session returns work without browser storage;
legacy-session routing depends on at least one available first-party storage area.
The existing authenticated app reconciliation, webhook settlement, immediate
confirmation UI, callback acknowledgement and cold-start delivery remain intact.
Return URLs never mark an order paid or change inventory, rewards or reservation
deadlines. The handoff adds no database polling or new background timers.

## Shared deployment

Deploy the website's static `mobile-payment.html` / JS / CSS and legacy return
guard before deploying the targeted `create-paymongo-checkout` change. The live
function was compared with the website repository first; the older mobile copy
must not replace the shared live implementation. No database migration is needed.
The independent legacy `mobile-payment-return` function retains provider
verification and receives only the corrected URI path and a network timeout.
