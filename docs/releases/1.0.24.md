# Mobile reliability release 1.0.24

Scope: customer mobile repository only. The customer website source and hosting were not changed.

## Changes

- Atomic mobile COD checkout combines order creation, reward application and mobile attribution in one transaction. A persisted intent key recovers the same order after an interrupted response.
- Native PayMongo monitoring captures the order and monitor generation before requesting status. Obsolete results cannot complete a later checkout.
- Checkout blocks back navigation while submitting and suppresses handoff after unmount. Online payment retains its email-OTP authorization and original item ordering.
- Temporary role-read failures no longer sign a customer out. Confirmed non-customer roles are still rejected.
- Cart mutations are serialized, remain immediately responsive, and roll back visibly on failure. Checkout waits for pending cart writes. Clear-bag uses the same reliable path.
- Realtime customer refreshes check ownership and request revision. Catalog and order changes are coalesced and fetch changed IDs. Explicit API pages avoid default row-cap truncation.
- Order lines use their saved product name, unit price and image instead of changing historical details when the catalog changes.
- Assistant requests have deadlines, conversation-generation checks and retry text preservation.
- Reconnect no longer runs duplicate catalog downloads. Failed images alone are retried; the unused CacheStorage prefetch was removed.
- HEIC photos are converted locally to JPEG using a lazy, packaged decoder. Ordinary images are resized to a maximum 1600-pixel side when supported. No third-party conversion upload is used.
- Review upload paths are content-addressed for retry reuse. Newly created objects are removed following pre-publication failures or confirmed database rollback; ambiguous publication responses retain objects to avoid deleting an already published photo.
- Filter reset consistently restores the PHP 500,000 ceiling; selected subcategories no longer duplicate the product grid.
- iOS minimum app target is 16.0 instead of 26.0; the iOS-26-specific appearance remains conditional. Android minimum SDK remains 24. Supported OS versions are not a promise of compatibility with every hardware/WebView combination.
- Two mobile foreign-key indexes were deployed without changing website RLS policies.

Existing uncommitted customer-mobile onboarding, phone/OTP, FAQ and responsive checkout work was preserved and included in this release.

## Verification

- Storefront TypeScript and 167 tests passed.
- Angular lint and 13 native-shell browser tests passed, including a replaced-payment race regression.
- Production storefront/shell builds, Android debug build and iOS Simulator build succeeded.
- Signed iPhone device build succeeded and version 1.0.24 was installed on the paired Prince iPhone 17. Installation is verified; authenticated shopping/payment behavior has not been exercised on that phone.
- 24 Chromium layout samples across 320, 360, 390, 430, 768 and 844 pixels, including landscape and extra-large text, had no measured horizontal overflow.
- Actual HEIC fixture conversion produced a renderable 1280 x 854 JPEG (342,205 bytes).
- Live SQL transaction tests checked order/reward rollback, one-order retry, one stock reservation, mobile attribution, changed-intent rejection and missing-auth rejection. Test rows were rolled back; no fixture users remain. PostgreSQL order sequences may contain harmless gaps from rolled-back tests.
- Anonymous checkout execution and direct client reads of private checkout intents are denied. Both new mobile indexes were verified.
- Production npm dependency audits reported zero vulnerabilities at verification time.

## Explicit remaining boundaries

- Built-in Supabase leaked-password protection could not be enabled: the organization is on Free and the feature requires Pro. No paid upgrade was made. See https://supabase.com/docs/guides/auth/password-security.
- Full history currently remains eagerly assembled through explicit API pages. Targeted realtime updates reduce recurring egress, but lazy order-detail screens and user-driven history pagination are further optimization work, not delivered here.
- Existing unrelated shared-database advisory notices were not blindly silenced: staff/OTP security-definer routines, deny-by-default tables, website policies and unused-index notices require separate ownership-aware review.
- No physical-device payment, actual OTP email delivery, push delivery or exhaustive low-memory/accessibility validation was performed. Automated tests and successful compilation do not substitute for those checks.
- New client behavior requires installing the rebuilt native app. A database deployment or Git push alone does not update an already installed APK/IPA. This repository has no configured over-the-air web release channel.
