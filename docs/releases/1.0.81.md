# CozyCraft Mobile 1.0.81 — Realtime recovery and lower-egress shopping

Based on 1.0.80 (`292472f`). Android versionCode **82**; iOS version
**1.0.81**, build **69**. Release checks performed on October 4, 2026.

## Improvements

- Shared, serialized catalog cache: one full startup request, then a small
  ID/timestamp manifest and changed-product reads on recovery. Concurrent auth,
  focus and reconnect paths no longer independently reload the full catalog.
- Visible/online/native-resume recovery for shopping and account data, with
  staleness gates, coalesced requests and identity/revision guards. No new
  background polling interval. Failed initial account hydration can retry on
  reconnect, resume or pull-to-refresh instead of permanently blocking readiness.
- Five-row pages for order, public review, support-ticket and reward history.
  Full-account order counts and full-product review ratings remain accurate.
  Older orders retain details, invoice, review and payment-resume actions.
  Page controls recover when moderation/deletion removes the last page.
- Only usable, unexpired rewards are loaded into the wallet; historical rewards
  load on demand. Address/payment/support sections fetch only when needed.
- Safe realtime invalidation topics refresh delivery areas and reviews even
  when RLS makes a deactivated, hidden or deleted source row invisible. The new
  public signal table contains only topic/timestamp and has no client write grant.
- Public product photos use responsive 320/640/960/1440px CDN variants, native
  lazy loading and a one-time original fallback. Original full-screen images
  remain available. Private avatars, signed URLs and review photos are excluded
  from the public transformation allowlist. No second full-size download is
  made merely for thumbnail canvas/crop analysis.
- Noncritical local snapshot serialization is deferred off the immediate input
  path, with page-hide flushing and account-owner guards. Auth/payment intent
  writes remain immediate. Existing reduced-motion/economy behavior is retained.
- Removed stale deployable copies of the shared checkout/payment verification
  functions. Their history is recoverable in Git; the website repository remains
  authoritative. Added an executable release/ownership gate and ownership docs.
- Patched Angular framework to 20.3.33, Angular build tools to 20.3.37 and
  compatible transitive Piscina/webpack middleware security fixes. The shared
  website also received DOMPurify 3.4.16.

  including an initial order-service outage, 12-order pagination, older-order

  The fixtures observed one full catalog read at startup and no second full

## Deployment and verification boundaries

The shared project migration
`20261004090000_mobile_bounded_reads_and_recovery.sql` is deployed, including the
review RPC and realtime signals. Netlify production was updated. No payment
settlement, inventory or discount-budget rules were changed. See
[backend ownership](../backend-ownership.md) before deploying shared functions.

The native package still needs installation: the GitHub APK is **debug-signed
for testing**, not a Play Store submission. Build/run `ios/App/App.xcodeproj`
through Xcode for iPhone. No phone installation, App Store/TestFlight upload,
real payment or customer-message test was performed. Apple background push
still requires the owner's APNs credentials.

Full development-tool auditing still reports **25 affected dependency nodes
(21 high, 4 moderate; 0 critical)**, rooted in `braces`, `http-cache-semantics`
and older transitive `uuid`. The first two currently have no published patched
version: [braces advisory](https://github.com/advisories/GHSA-vfj7-8cjw-p6xm) and
[cache advisory](https://github.com/advisories/GHSA-ch52-4w7c-c8xp). These are
development dependencies, not included as runtime packages in the released
app. Keep build/test servers local, use trusted source/dependencies and re-audit
when upstream fixes ship. Breaking toolchain downgrades were not forced.

The local `npm run verify:release` gate is available. Hosted GitHub Actions
remains unconfigured because the connected token lacks workflow authorization.
This release extracts the critical cache/recovery/media/paging helpers; it does
not replace the existing dual-framework shell or fully split the large
Storefront component. Further structural refactoring and real-device
performance profiling should remain incremental and separately verified.
